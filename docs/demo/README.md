# 演示：RTOS 任务切换回放（真板实测数据）

这个目录里是两份**真板实测数据**的可交互回放页，不是示意动画。

![SVCrtOS 任务切换无缝 trace 回放](trace-replay-swd.png)

## 一、SWD 无缝录制版（推荐先看）

`trace-replay-swd.html` —— 只接 **SWD 两线**，把 8 KB RAM 环里的压缩事件流**增量搬走**，
一条连续录制、零丢失。

- **板子**：STM32F401（Cortex-M4）@ SYSCLK 84 MHz，跑 SVCrtOS（SVC 特权隔离 RTOS）
- **采集**：内核插桩（上下文切换、SysTick 进出、PendSV 进出、HardFault 等故障向量、阻塞让出）
  → 目标侧 token 压缩进 8 KB 静态环 → 主机每 120 ms 经 SWD 搬一段
- **本次规模**：5.36 s 连续录制 / 56,355 条事件 / 5,386 次上下文切换 / 24,136 次中断进出，
  **0 条丢失**，编码后 **3.67 字节/事件**（相对 12 B 记录 **3.27×**）
- **时间戳**：目标侧 `DWT_CYCCNT`（11.9 ns/拍），微秒级切片也分辨得出来

```
trace_instrument(backend="swd", swd_bytes=8192)
  → trace_swd_status(...)   # 环容量 / 未读字节 / lost_events / 压缩比
  → trace_swd_read(..., out_file="trace.json")   # 搬走未读段并解成事件
  → （循环：跑一段 → 搬一段）
```

### 为什么能"无缝"

1. **目标侧先压缩**：每次事件编成 token，命中字典只写 1 字节槽号 + 变长时间差，
   新键才写全量四元组 `(type, kind, id, arg)`。
2. **背压而不是覆盖**：环满时丢新事件并计数（`lost_events`），**绝不覆盖没搬走的区域**。
   于是任何时刻停下，已经录下的那一段都是完整的。

### 前提与边界（页面里也写着）

- 事件率约 10k/s 时，8 KB 环只够 **0.22 s**，**搬运间隔必须短于这个窗口**
  （实测 0.25 s 丢 29,015 条；0.12 s 丢 0 条）。
- 读环要**停机**：Keil 链路全速运行时读 SRAM 可能整片读回 0。
  停机搬走不会丢数据——这是背压给的保证。
- 这条路要先**插桩**（编译期改代码），它解决的是「板子只焊了 SWD 两线」这个场景，
  不替代 SWO/RTT/ETM。怎么选见 `trace_guide`。
- 只记录了**插了桩**的那些事：图上没有 ≠ 没发生。

### 页面通道

| 通道 | 它想说明的事 |
|---|---|
| **任务泳道** | 每个上下文一条泳道，只画自己运行的区间。**同一像素列里只会亮一条**——单核没有分身 |
| **上下文切换带** | 每次切换一根竖线（按切出任务着色），放大后能看到切向谁 |
| **PendSV / SysTick** | 关键中断的进出活动：视野内次数多时画密度条，放大后逐个画真实的进入-退出区间 |
| **阻塞/让出** | 任务主动让出 CPU 的时刻，按任务着色 |
| **顶部徽章** | 事件数、丢失数、压缩率、环容量、搬运间隔——先把可信度摊开 |

## 二、全速跑 + 事后搬走版

`trace-replay-singlecore.html` —— 目标全速跑、录制期间一次都不停，事后一次性把
24 KB 缓冲搬出来。

- **规模**：30,800 条记录 / 20,523 次上下文切换 / 10,277 次阻塞事件
- **代价**：录制期间**不 halt 目标、不用 SWO/ETM**；但缓冲写满会覆盖最旧的记录，
  且分块导出之间存在空洞

```
trace_instrument(backend="buff", buff_records=2048, buff_ts_shift=0)
  → trace_buff_status(...)      # total / lost / wrapped
  → trace_buff_dump(..., out_file="trace.json", names="0x10=switch,0x11=wait")
  → trace_buff_reset(...)
```

这一版页面刻意把「单核」画在脸上：CPU 占用带同一时刻只有一种颜色，每任务电平
**同一像素列里只会亮一条**；分块导出期间没记录的时间段用**斜纹带**明示，
不要当成"目标没跑"。它也会承认自己的边界：统计百分比的分母是**有效覆盖时间**
（已扣掉导出空洞），拿录制总时长当分母会把占用率系统性压低。

两版的取舍：`buff` 追求**对目标零扰动**（全速跑，但会丢最旧记录、块间有空洞）；
`swd` 追求**一条连续不丢**（要主机周期搬运，搬的时候目标停机）。
先想清楚这次要回答的问题，再选后端。

## 打开方式

两个页面都是**单文件、无外部依赖、无网络请求**，用浏览器直接打开即可：

- 滚轮缩放（以鼠标为锚点）、按住拖动平移、单击定位游标、双击全览
- `▶ 回放` 按 1:1 实时推进游标
- `切换标记 / 中断活动 / 阻塞事件` 三个通道可单独开关

> gitee 只能预览 HTML 源码，**clone 下来双击文件**才是交互页面。
> 数据内嵌在文件里（`buff` 版约 1 MB、`swd` 版约 0.7 MB），页面用 canvas 直接绘制。
